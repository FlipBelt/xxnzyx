# FLIPBELT 移动端重构三阶段实施方案

## 总体决策

本次重构分三阶段，每阶段四项，共十二项。每阶段完成后独立构建、测试、提交和验收；上一阶段未通过，不进入下一阶段。最终素材未交付不阻塞重构，前台通过新版固定素材槽位显示占位状态，后续从后台上传即可生效，无需重新构建 H5。

滑动方向按业务当前口径实现：手指左滑返回上一页，手指右滑进入下一页。点击“下一步”始终进入下一页，右上角提供返回上一页入口。第一、第二页完成后锁定，第三至第七页允许返回。

## 第一阶段：基线、存储与素材接口

### 1. 建立可回退基线

实施：

- 保留线上快照 `/srv/flipbelt-challenge-backups/pre-refactor-20260826-091837`，不得删除或覆盖。
- 审计本地 `.gitignore`，确认 `.env`、上传目录、虚拟环境和日志不会进入 Git。
- 将当前本地源代码建立首个基线提交，并创建重构前标签。
- 从基线创建 `codex/mobile-refactor` 分支，后续每阶段单独提交。

完成标准：Git 工作区有可追溯基线；线上快照校验和与数据库备份保持可读；任何阶段都能按明确路径恢复。

### 2. 切换为 ECS 本机存储

涉及：`backend/app/services/storage.py`、`backend/app/main.py`、后端环境配置、两份 Nginx 站点配置。

实施：

- 生产环境使用 `STORAGE_BACKEND=local`，保留 OSS 实现但不启用。
- 上传目录固定为 `/srv/flipbelt-challenge/uploads`，目录权限仅允许应用写入、Nginx 读取。
- 增加 `/uploads` 静态挂载兜底，并让 Nginx 优先直接服务 `/flipbelt-api/uploads/`。
- 为 `/flipbelt-api/assets/` 和 `/flipbelt-api/uploads/` 设置正确 MIME、Range、ETag/Last-Modified 和缓存响应。
- 上传目录独立于 H5、后台和后端代码的原子部署目录。

完成标准：后台上传一个小文件后得到同域 HTTPS URL；浏览器返回 200；视频 Range 请求返回 206；重启后文件仍存在；全过程不访问 ECS RAM 元数据。

### 3. 建立新版固定素材槽位

涉及：`backend/app/services/activity.py`、后台 API 类型、前台 API 类型。

新版槽位：

- `demo_video_portrait`
- `demo_video_poster_portrait`
- `challenge_rule_portrait`
- `score_reward_portrait`
- `douyin_qr`
- `douyin_open_link`

实施：

- 继续复用现有 `media_assets` 表和通用上传接口，不新增不必要的数据表。
- 新版前台只读取带 `portrait` 的三个核心槽位，因此旧视频和旧规则图保留但不会误显示。
- 不创建空 URL 记录；槽位缺失即代表素材尚未交付。
- 上传使用 UUID 对象路径，替换素材时自动绕过旧缓存。
- 上传失败错误统一改为“媒体存储失败”，不再固定写成“OSS 上传失败”。

完成标准：API 可以同时保留旧素材和新版槽位；缺少新版素材时接口正常返回；上传新版素材后无需重新构建前台即可读取新 URL。

### 4. 重做后台素材管理区

涉及：`apps/admin/src/App.vue`、`apps/admin/src/services/api.ts`。

实施：

- 将当前任意媒体表格改成六个固定槽位卡片。
- 每个槽位显示“未上传/已上传”、文件类型、预览、更新时间和替换按钮。
- 图片上传前在浏览器读取尺寸，非 `1080×1920` 时明确警告并阻止误上传。
- 视频上传前读取分辨率、时长和 MIME；要求 MP4、9:16，并提示必须使用 H.264。
- 抖音外链使用普通 HTTPS 文本输入，不作为文件上传。
- 替换只更新数据库指向，不自动删除旧文件，保证可恢复。

第一阶段出口：后台可以在不使用 OSS 的情况下上传、预览和替换测试素材；公开 H5 尚不切换到新版页面。

## 第二阶段：移动端页面与业务流程

### 5. 重构为七页响应式步骤器

涉及：`apps/participant/src/pages/index/index.vue` 及样式文件。

实施：

- 删除三层卡堆、3D 透视、飞出缩放、历史小卡和整卡拖拽代码。
- 保留现有背景、卡片配色、品牌标题和七个业务步骤。
- 同一时间只渲染当前步骤；切换使用 180–240ms 的轻量横向过渡。
- 页面使用 `100dvh`、安全区和正常纵向滚动，不再使用固定 `1420rpx/820rpx/720rpx` 页面高度。
- 媒体区使用弹性布局，底部为独立操作区。

完成标准：320×568 到 430×932 的主流视口均不横向溢出；内容可见；地址栏高度变化不遮挡按钮。

### 6. 实现按钮、滑动和返回

实施：

- 下一步按钮居中、中等宽度、高对比度，文案明确下一步去向。
- 点击下一步进入下一页。
- 手指左滑返回上一页，手指右滑进入下一页。
- 右上角显示“返回上一页”；不可返回时隐藏或禁用。
- 横向位移达到阈值且明显大于纵向位移才翻页。
- `input`、`button`、`video` 和视频控制条不参与页面手势识别。
- 转场中加锁，防止连续点击或连续滑动跳过页面。

完成标准：按钮和三种导航方式结果一致；纵向滚动、输入和拖动视频进度条不会误翻页；第一、第二页完成后不可返回。

### 7. 调整报名文案和输入校验

涉及：主流程报名页、旧独立报名页、前后端报名 Schema 和路由。

实施：

- 删除“号码牌由你自行保留”，只保留“每人仅可挑战一次”。
- 姓名只校验非空，不限制字符格式。
- 手机号严格校验 11 位数字。
- 号码牌只校验非空，不添加前缀、位数、正则或示例限制。
- 删除前端 `A018/A001` 示例；后端不再强制将号码牌转换为大写，保留用户原始填写内容。
- 同一活动内手机号和号码牌唯一约束保持不变。

完成标准：中文、英文及混合姓名可提交；各种非空号码牌可提交；非 11 位手机号不能提交；重复号码牌仍被拦截。

### 8. 修正重复报名和已有成绩流程

实施：

- 每次打开二维码都从第一页开始，不从本地缓存恢复步骤。
- 第二页提交重复身份时恢复原 token 和报名记录，但统一进入第三页。
- 不论是否已有成绩，都不从第二页直接跳第六或第七页。
- 第六页读取成绩状态：无成绩显示“刷新我的成绩”，有成绩显示“查看我的已有成绩”。
- 只有用户点击后才进入第七页。
- API 错误区分“身份可恢复”和“号码牌被其他身份占用”，避免错误恢复。

第二阶段出口：使用无成绩旧用户、有成绩旧用户和新用户三类数据走通七页流程；移动端不依赖最终媒体素材。

## 第三阶段：媒体体验、抖音、成绩接口与上线

### 9. 完成视频组件和空素材状态

实施：

- `demo_video_portrait` 不存在时不显示旧视频，中央显示“示范视频正在更新，可点击下一步继续”。
- 素材存在时显示封面、加载状态、播放按钮和错误重试。
- 禁止强制自动播放；播放失败不阻断下一步。
- 只在进入视频页时加载视频元数据，离开页面后暂停。
- 正式素材要求 H.264/AAC/Fast Start；部署验收检查首播、重播、弱网和 Range。

完成标准：空槽位无破图；视频加载失败有明确反馈；第一次播放和第二次播放行为一致；视频控制不触发翻页。

### 10. 完成规则图和计分奖励图热替换

实施：

- 分别读取 `challenge_rule_portrait` 和 `score_reward_portrait`。
- 缺失时显示统一占位，不回退到旧横图或低分辨率图片。
- 图片在可用区域内 `contain` 显示，页面背景负责填满不同长宽比设备。
- 设计师交付后由后台上传，前台刷新活动配置即可显示。
- 顶部说明和底部按钮由 HTML 渲染，不写入图片。

完成标准：上传 `1080×1920` 新图后无需构建或部署前端；iPhone/Android 不裁掉规则文字和按钮。

### 11. 修正抖音关注入口

实施：

- 保留抖音平台码图片。
- 增加 `douyin_open_link` 配置和“打开抖音关注”按钮。
- 配置了有效 HTTPS 分享链接时优先显示按钮；未配置时显示“请截图后使用抖音扫一扫”。
- 小红书保持现有二维码逻辑，但同样使用清晰的操作说明。
- 外链打开失败时仍保留二维码备用，不阻塞下一步。

完成标准：有链接、无链接、链接打开失败三种场景都有明确退路；iPhone 不再依赖 Safari 长按识别抖音码。

### 12. 预留个性化成绩接口并完成发布验收

实施：

- `/me` 数据结构预留 `official_rank`、`display_rank`、`display_title`；当前 `display_rank` 可为空。
- 后台排行榜、公开排行榜、奖励和抽奖只使用真实得分与真实排名。
- 个人页优先展示 `display_title`；个性化排名算法未确认前不伪造数值。
- 执行管理后台构建、域名 H5 构建、IP 路径 H5 构建、后端静态检查和测试。
- 使用 320×568、375×667、390×844、430×932、360×800、412×915 视口验收。
- 线上部署继续使用时间戳临时目录、文件校验、原子切换；Nginx 先 `nginx -t` 再 reload；仅后端变更时重启 `flipbelt-challenge`。
- 部署后验证 HTTP 301、HTTPS 200、API health、素材 200/206、管理后台、手机 User-Agent、新旧报名和成绩流程。
- 最后使用至少一台 iPhone 和一台 Android 真机验收。

第三阶段出口：新版流程正式上线；最终素材可以随后从后台上传热替换；个性化成绩算法作为独立后续任务，不影响本次重构上线。

- 第二阶段提交：`mobile-stepper-and-flow`
